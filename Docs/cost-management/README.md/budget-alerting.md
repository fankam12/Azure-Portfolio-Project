# Azure Subscription Budget & Cost Alerting

## Overview

This implementation establishes subscription-level cost governance for the Azure HomeLab environment using **Azure Cost Management**.

A monthly Azure Budget is configured at the subscription scope to monitor spending across all resource groups and workloads within the subscription.

The purpose of this implementation is to:

* Detect unexpected Azure spending
* Provide early warning of projected cost increases
* Monitor actual monthly cloud consumption
* Establish basic FinOps and cloud governance practices
* Prevent unnoticed resource consumption during infrastructure testing

---

## Architecture

**Azure Subscription:** HomeLab
**Monthly Budget:** $200
**Scope:** Subscription

```text
HomeLab Subscription
│
├── DevLab_RG
├── HomeLab_RG
├── Bicep-Chapter2
├── Future Resource Groups
│
└── Azure Cost Management
      │
      └── Monthly Budget: $200
            │
            ├── Forecasted Cost Alert — 75%
            │
            ├── Actual Cost Alert — 70%
            │
            ├── Actual Cost Alert — 85%
            │
            └── Actual Cost Alert — 100%
```

Because the budget is configured at the **subscription scope**, costs generated by all resource groups and workloads within the HomeLab subscription contribute toward the monthly budget.

## Budget Configuration

| Setting       | Configuration            |
| ------------- | ------------------------ |
| Budget Name   | `HomeLab_Monthly_Budget` |
| Scope         | Azure Subscription       |
| Budget Amount | $200                     |
| Reset Period  | Monthly                  |
| Category      | Cost                     |
| Start Date    | August 1, 2026           |

The budget was configured at the HomeLab subscription scope, allowing Azure Cost Management to monitor costs generated across the entire environment.

## Alert Strategy

Multiple thresholds were configured to provide progressive visibility into both actual and forecasted Azure spending.

| Alert Type      | Threshold | Amount | Purpose                                                                 |
| --------------- | --------: | -----: | ----------------------------------------------------------------------- |
| Actual Cost     |       70% |   $140 | Early warning based on actual Azure consumption                         |
| Forecasted Cost |       75% |   $150 | Warning when Azure predicts monthly spending may approach the budget    |
| Actual Cost     |       85% |   $170 | Escalated warning as actual spending approaches the monthly budget      |
| Actual Cost     |      100% |   $200 | Notification when actual spending reaches the configured monthly budget |

### Forecasted Cost Alert

The forecasted cost alert provides an early indication that current resource consumption may result in higher-than-expected monthly spending.

At **75% of the $200 monthly budget**, the forecasted threshold corresponds to:

```text
75% × $200 = $150
```

Unlike an actual cost alert, this threshold considers Azure's projected spending for the remainder of the billing period.

This allows corrective action to be considered before the full monthly budget is consumed.

Potential corrective actions include:

* Reviewing Azure Cost Analysis
* Identifying unexpected resource consumption
* Deallocating unused virtual machines
* Removing temporary or test resources
* Reviewing high-cost Azure services
* Investigating unexpected changes in resource consumption

### Actual Cost Alerts

Actual cost alerts provide checkpoints based on Azure consumption that has already occurred.

Three actual-cost thresholds were configured:

* **70% ($140)** — Initial actual-spend warning
* **85% ($170)** — Escalated warning as spending approaches the budget
* **100% ($200)** — Notification that the configured monthly budget has been reached

Using multiple thresholds provides increasing visibility as monthly cloud consumption approaches the established budget.

---

## Important Consideration

Azure Budgets provide **cost monitoring and notifications but do not function as a hard spending limit**.

Reaching the configured **$200 monthly budget does not automatically stop, disable, or deallocate Azure resources**. Resources can continue operating and generating charges after the budget threshold has been reached.

The configured alerts therefore function as an **early-warning and cost-governance mechanism**, allowing unexpected spending to be identified before additional operational action is taken.

Automated remediation can be implemented separately using services and automation capabilities such as:

* Azure Monitor Action Groups
* Azure Automation
* Azure Logic Apps
* Event-driven automation workflows

For a production environment, these capabilities could be integrated with defined operational procedures to notify engineering teams or initiate approved remediation when specific cost thresholds are reached.

## Azure CLI Validation

The configured subscription budget can be viewed and validated using Azure CLI:

```bash
az consumption budget show --budget-name "HomeLab_Monthly_Budget" -o table
```

The expected output confirms the primary budget properties:

```text
Amount    Category    Name                    TimeGrain
--------  ----------  ----------------------  ---------
200.0     Cost        HomeLab_Monthly_Budget  Monthly
```

This validation confirms that the `HomeLab_Monthly_Budget` exists and is configured with:

* **Budget Amount:** $200
* **Category:** Cost
* **Time Grain:** Monthly

Using Azure CLI for validation provides an additional method of confirming the deployed configuration outside of the Azure Portal.
